
## **Контрольні запитання**

1. **Доставка «host-to-host» vs «process-to-process»:**
* **Host-to-host (мережевий рівень / IP):** Доставляє дані тільки **до пристрою/комп'ютера** в мережі.


* **Process-to-process (транспортний рівень / порти):** Доставляє дані **конкретній програмі** (браузеру, грі, месенджеру), яка працює на цьому комп'ютері.




2. **Що таке сокет:**
* Це комбінація **`IP-адреса + номер порту`**, яка точно визначає кінцеву точку зв'язку.




3. **Триетапне рукостискання TCP (Three-way handshake):**
* **1 крок:** Клієнт відправляє `SYN` (просить розпочати з'єднання).


* **2 крок:** Сервер відповідає `SYN-ACK` (погоджується і підтверджує).


* **3 крок:** Клієнт надсилає `ACK` (підтверджує готовність).




4. **Як ковзне вікно і таймаут гарантують надійність:**
* **Ковзне вікно:** Дозволяє відправляти декілька пакетів підряд без зупинки на кожне окреме підтвердження.


* **Таймаут:** Якщо відповідь (підтвердження) не надійшла вчасно, пакет автоматично надсилається повторно.




5. **Повільний старт vs Уникнення перевантаження:**
* **Повільний старт:** Обсяг даних, що відправляються, **подвоюється** з кожним колом.


* **Уникнення перевантаження:** Настає після певного порогу (`ssthresh`), де обсяг збільшується **повільно (лінійно)** по 1 пакету, щоб не забити мережу.




6. **Коли UDP кращий за TCP:**
* У сервісах **реального часу** (відеодзвінки, ігри, онлайн-трансляції, DNS-запити), де **швидкість важливіша за втрату кількох кадрів чи пакетів**.




7. **Чого немає в заголовку UDP:**
* Немає полів **номера послідовності (`seq`)**, **підтвердження (`ack`)** та **розміру вікна**. Вони не потрібні, бо UDP просто відправляє дані без перевірки доставки чи встановлення з'єднання.




8. **Чому закриття TCP називають «4-way termination»:**
* З'єднання двостороннє. Спочатку клієнт закриває свій напрямок (`FIN` -> `ACK`), а потім сервер окремо закриває свій (`FIN` -> `ACK`) — разом **4 пакети**.




9. **Порти 6000-6111 та фільтр у Wireshark:**
* Вони належать до **зареєстрованих (1024-49151)**, бо діапазон *well-known (0-1023)* зайнятий системними службами та вимагає прав адміна.


* Фільтр **`tcp.flags.syn == 1`** показує лише ті пакети, де встановлено прапорець `SYN` (тобто початок рукостискання).





## **Домашнє завдання**

### **1. Задача на рукостискання TCP**

* **Дано:** Клієнт `seq = 1000`, Сервер `seq = 2000`.


* **Пакет 1 (Клієнт -> Сервер):** Прапорець `SYN`, `seq = 1000`, `ack` — відсутній.


* **Пакет 2 (Сервер -> Клієнт):** Прапорці `SYN, ACK`, `seq = 2000`, `ack = 1001`.


* **Пакет 3 (Клієнт -> Сервер):** Прапорець `ACK`, `seq = 1001`, `ack = 2001`.




### **2. Вибір між TCP і UDP**

* **Завантаження вебсторінки:** **TCP** (потрібно завантажити весь текст і скрипти без втрат).


* **VoIP телефонія:** **UDP** (важлива затримка в реальному часі, втрату пари мілісекунд звуку ніхто не помітить).


* **Онлайн-гра в реальному часі:** **UDP** (важливий найнижчий пінг, застарілі координати гравця непотрібні).


* **Передача файлу по FTP:** **TCP** (файл має передатися на 100% цілим і без пошкоджень).
