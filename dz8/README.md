## Контрольні запитання

### 1. Відмінність асемблера від мов високого рівня та машинного коду

* Від мов високого рівня (C, Python, Java): асемблер позбавлений високорівневих абстракцій (об'єктів, типів даних, складних структур). Кожна інструкція асемблера напряму відображається в одну конкретну дію процесора над його регістрами чи пам'яттю.
* Від машинного коду: замість послідовностей двійкових чи шістнадцяткових чисел (наприклад, 0x005B0533), які зчитує схема процесора, в асемблері використовуються буквені мнемоніки (add, sw, jal) та текстові імена регістрів.

### 2. Особливість регістра x0 у RISC-V

Регістр x0 (zero) апаратно замкнений на значення 0. Читання з нього завжди повертає 0, а будь-яка спроба записати в нього нові дані просто ігнорується процесором. Це дозволяє спростити систему команд - наприклад, порожня операція nop реалізується як addi x0, x0, 0, а копіювання значення між регістрами - як додавання з x0.

### 3. Регістри ABI для аргументів і повернення значень

* Передача аргументів: регістри `a0` - `a7` (фізичні регістри x10 - x17).
* Повернення результату: регістр `a0` (за потреби повернення 64-бітного значення на 32-бітній архітектурі додається `a1`).

### 4. Директиви .data та .text

* `.data`: оголошує сегмент пам'яті, де створюються й ініціалізуються статичні змінні, текстові рядки, константи та масиви.
* `.text`: позначає сегмент, у якому розміщуються безпосередньо машинні команди (інструкції програми).

### 5. Послідовність дій при виклику підпрограми

1. Підготовка аргументів: викликаюча програма розміщує значення у регістрах a0`–`a7.
2. Перехід: інструкція jal ra, Label зберігає адресу наступної команди у регістр ra і передає керування на підпрограму.
3. Пролог: викликана функція зберігає значення ra та необхідних s-регістрів у стек.
4. Обчислення: виконується основний код функції.
5. Епілог: відновлюються раніше збережені значення зі стеку.
6. Повернення: команда ret (псевдоінструкція для jalr x0, 0(ra)) повертає виконання за адресою з ra.

### 6. Відмінність доступу до пам'яті (RISC-V vs x86)

* RISC-V (Load/Store): арифметика з пам'яттю заборонена. Спочатку виконують завантаження комірки в регістр командою lw, і лише наступною інструкцією add виконують додавання.
* x86 (CISC): дозволяє суміщати вибірку з RAM та додавання в єдиній команді add eax, [ebx].

### 7. Призначення s-регістрів (callee-saved)

Регістри s0`–`s11 називають *callee-saved*, оскільки викликана підпрограма зобов'язана зберегти їхні початкові значення у стек перед їх зміною і відновити їх перед виходом. Якщо цього не зробити, викликаюча програма втратить власні локальні дані, що були записані в цих регістрах.

### 8. Номери сервісів ecall у RARS (a7)

* Виведення цілого числа: 1
* Виведення текстового рядка: 4
* Завершення програми: 10

### 9. Масштабування індексу масиву int

* Оскільки змінна int займає 4 байти, а адресація пам'яті байтова, позиція $i$-го елемента знаходиться за зміщенням $i \times 4$ від початку масиву.
* Найшвидше це множення виконується побітовим зсувом ліворуч на 2 розряди командою `slli rd, rs, 2`.


## Домашнє завдання

### 1. Підпрограма cube(x) на RISC-V

cube:
    mul t0, a0, a0    # t0 = x * x (квадрат числа)
    mul a0, t0, a0    # a0 = t0 * x (куб числа)
    ret               # повернення з підпрограми


### 2. Покрокова зміна регістрів (a0, ra)

* До виклику (після `li a0, 6`):
* a0 = 6
* ra = початкова адреса повернення з main

* У момент виконання `jal ra, square`:
* a0 = 6
* ra = адреса інструкції в main, що йде одразу за викликом jal

* Усередині `square` (після обчислення `mul`):
* a0 = 36
* ra = адреса повернення в main (залишається незмінною)

* Після повернення (`ret`):
* a0 = 36
* ra = відновлена адреса в main

### 3. Рядки з відмінністю в обробці пам'яті

* У RISC-V: lw t0, 0(x6) - явна окрема команда для вибірки значення з пам'яті в буферний регістр t0.
* У x86: add eax, [ebx] - команда суміщає читання даних за адресою [ebx] і додавання до eax без проміжних команд завантаження.
