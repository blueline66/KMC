# Домашнє завдання та контрольні запитання (Лекція №20)

## Контрольні запитання

1. **Етапи проєктування мережі:**
   1. Вимоги (що потрібно зробити).
   2. Логічна схема (сегменти та порти).
   3. Фізична схема (обладнання та кабелі).
   4. Адресний план (IP-адресація).
   5. Документація (схеми й конфігурації).

2. **Три рівні ієрархічної моделі:**
   * **Access (доступ):** Підключення пристроїв користувачів (ПК, принтери, Wi-Fi).
   * **Distribution (розподіл):** Об'єднання трафіку з рівня доступу, фільтрація та маршрутизація між VLAN.
   * **Core (ядро):** Високошвидкісна центральна магістраль для швидкого пересилання трафіку.

3. **Bridge vs Host режими контейнерів:**
   * **Bridge:** Контейнер має свою віртуальну IP-адресу, відрізаний від хоста та виходить назовні через NAT.
   * **Host:** Контейнер використовує мережу комп'ютера (хоста) напряму без ізоляції.

4. **Що таке VPC та її елементи:**
   * **VPC (Virtual Private Cloud):** Ізольована віртуальна мережа у хмарі.
   * **Елементи:** Підмережі (Subnets), Групи безпеки (Security Groups), Балансувальники навантаження (Load Balancers).

5. **SNMP та NetFlow при моніторингу:**
   * **SNMP:** Показує стан пристроїв (завантаження процесора, температура, помилки портів).
   * **NetFlow:** Збирає статистику трафіку (хто, куди, скільки даних передає).

6. **Чому важлива документація:**
   * Актуальна схема дозволяє швидко знайти та усунути аварію за 10–15 хвилин замість кількох годин відновлення мережі «з голови».

7. **Чому звернення за іменем працює в bridge, але не в host:**
   * У **bridge** працює вбудований Docker DNS, який автоматично переводить ім'я служби в IP. В **host** такого DNS немає, тому треба звертатися через `localhost` або зовнішні адреси.

8. **Чому `0.0.0.0/0` — це порушення принципу найменших привілеїв:**
   * Відкривати вхід з `0.0.0.0/0` для внутрішньої бази даних небезпечно. Це відкриває доступ усім з інтернету й створює зайву поверхню для атак.

9. **Порядок діагностики недоступності сервісу:**
   1. *Перевірка DNS та порту:* Чи резолвиться ім'я та чи відкритий порт.
   2. *Health check:* Чи відповідає сам застосунок (чи не впав).
   3. *Логи та мережа:* Аналіз логів, маршрутів і фізичного зв'язку.


## Домашнє завдання

### 1. Логічна схема мережі офісу

* **Рівень Core (Ядро):** Головний маршрутизатор із 2 провайдерами (Основний + Резервний).
* **Рівень Distribution (Розподіл):** L3-комутатор для між-VLAN маршрутизації.
* **Рівень Access (Доступ):** L2-комутатори з підключенням ПК і серверів.
* **Адресний план (VLSM):**
  * `VLAN 10` (Відділ 1): `192.168.1.0/26`
  * `VLAN 20` (Відділ 2): `192.168.1.64/26`
  * `VLAN 30` (Відділ 3): `192.168.1.128/26`
  * `VLAN 40` (Сервери/Веб): `192.168.1.192/27`

### 2. Порівняльна таблиця режимів мереж контейнерів

| Режим | Рівень ізоляції | Швидкість | Типовий випадок використання |
| :--- | :--- | :--- | :--- |
| **Bridge** | Високий (власна віртуальна мережа) | Середня (є накладні витрати NAT) | Звичайні вебзастосунки, де кілька контейнерів спілкуються між собою. |
| **Host** | Відсутній (використовує мережу хоста) | Максимальна (прямий доступ) | Високонавантажені сервіси, де важлива кожна мілісекунда затримки. |
| **Overlay** | Високий (віртуальна мережа між хостами) | Нижча (через шифрування/тунелювання) | Кластери з кількох серверів (Docker Swarm, Kubernetes). |
